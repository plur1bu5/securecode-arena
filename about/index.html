A defensive benchmark for generated code

SecureCode Arena measures how often AI coding models introduce security vulnerabilities when they are asked only for useful functionality. It does not measure how well a model can find or exploit bugs.

What the study measures

Each of 9 models answered the same 16 prompts three times (432 files). After a parse and compile gate (427 valid, 5 invalid), remaining files were scanned with Bandit 1.9.4, Gosec (dev), Semgrep 1.182.1. Findings were deduplicated on (CWE, line) and mapped to severity.

The headline number is secure rate: the share of prompts with no targeted HIGH or MEDIUM finding in any repetition. Four cloud models tie at 14/16 secure (87.5%). The three local SLMs are each secure on 11/16.

Functional correctness is not scored. A program that compiles and still concatenates SQL is a vulnerability. A program that fails to parse is invalid, not secure.

The gap this fills

Hasan et al. (2026) evaluated 20 SLMs (0.4B to 10B) on HumanEval, MBPP, Mercury, HumanEvalPack and CodeXGLUE. They reported pass@k, VRAM, latency, and multilingual performance. Section 5.1 of that paper states that those metrics do not account for the security of generated code. A function can pass every unit test and still contain command injection.

Concurrent work on secure code generation at agent scale, including LSCBench (Wu et al., 2026), likewise finds that functional success far outruns security. This study is complementary: it focuses on small local models versus cloud assistants, under a static-analysis protocol, with a Qwen size ladder.

The SLM versus LLM comparison is descriptive. Three local SLMs and six cloud LLMs is too small for significance tests. We report means: SLM mean targeted HIGH/MEDIUM rate 0.312, LLM mean 0.1563.

Models tested

Three local SLMs via Ollama on CPU, and six cloud LLMs via browser chat. Temperature 0.2 for SLMs. Browser defaults (unknown) for LLMs. Fresh chat per generation.

The Qwen ladder is intentional: Qwen2.5-Coder 1.5B, then 7B, then Qwen3-Coder Next (LLM). Llama 3.1 8B is a general-purpose control, not a code specialist.

Languages and projects

Python, Go and JavaScript. Hasan et al. found SLMs stronger on Python and weaker on Go. Six coding projects (authentication API, file service, database search, health monitor, session handler, plus a Python-only Fibonacci control) yield 16 prompts. Details live on Projects and Methodology.
